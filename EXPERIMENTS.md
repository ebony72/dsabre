# Experiment Ledger — every table/figure in the paper, and how to regenerate it

Written 2026-08-06 after a full consistency pass over `paper/dsabre.tex` and
`paper/appendices.tex` against `code/results/*.json` (see
`CHANGES_FROM_SUBMITTED.md` and the memory note
`pytket-64q-comparison-stale-2026-08` for what that pass found). Purpose: the
**next** revision round should be able to regenerate any table without
re-reading the paper to figure out which script produced it.

**How to use this file.** Find the table/figure label, run the command(s)
under it, check the output JSON against the "feeds" line, then re-run the
listed table-generator (if any) and paste its stdout into the `.tex` body
marked `% BODY GENERATED BY ... -- regenerate and paste`. Tables with no such
marker were hand-transcribed from a JSON snapshot at authoring time — that is
itself a known failure mode (see the 2026-08 staleness note below); prefer
adding an auto-paste marker and a generator script when you touch one.

**Environment.** All circuit QASM files live under
`~/Documents/telesabre/circuits/qasm_{n}/`, shared across sibling projects —
**never regenerate them in place** (see `CLAUDE.md`, "DO NOT regenerate
benchmark circuits with the installed MQT Bench"). The TeleSABRE binary is
`~/Documents/telesabre/TeleSABRE`; device JSONs under
`~/Documents/telesabre/devices/`. Run everything from `code/`. Router
convention: `dS` = `General_dSABRE_Router` (topological extended set), `dSE`
= `dSABRE_BurstExt` (BFS extended set, the `\dSABRE{}` of the paper — the
default everywhere except the one ablation row that names `dS` explicitly).

### Contributions bullet, "Substituting a topological-order extended set costs $7.2$–$10.9\%$ ... across the three suites, the gain growing with circuit size" — ❌ wrong independent of staleness, not just stale
This is **not** a staleness bug like the others — it doesn't match Section IV-C's own text for the *same* claim even before considering the Aug-6 fix (Section IV-C says 25q is "$-1.4\%$" / "within noise", 64q is "$6.3\%$"; neither is inside $[7.2,10.9]$). It also doesn't match a freshly-computed per-suite check:
```bash
cd code
python3 -c "
import json, math
def gmean(xs): xs=[x for x in xs if x]; return math.exp(sum(math.log(x) for x in xs)/len(xs))
orders = {'25q': ['ae','ghz','graphstate','qft','qnn','random'],
          '36q': ['bv','dj','qaoa','qpeexact','vqe_su2','wstate'],
          '64q': ['ae','ghz','graphstate','qft','qnn','random','qpeexact','qaoa','multiplier']}
for suite, order in orders.items():
    recs = {r['circuit']: r for r in json.load(open(f'results/results_{suite}.json'))['results']}
    dS  = gmean([recs[c]['routers']['dS']['eprs']  for c in order])
    dSE = gmean([recs[c]['routers']['dSE']['eprs'] for c in order])
    print(suite, f'{100*(dS-dSE)/dSE:+.1f}%')
"
```
No rerun needed — this is a direct recomputation from `results_{25,36,64}q.json`'s `dS` column (dS is *already* run alongside dSE in every `benchmark.py` pass). **Current (2026-08-06): 25q −1.4%, 36q +9.0%, 64q +15.4%.** Note Table `tab:mech` in the main paper only ever shows 25q/64q — the "three suites" framing needs a 36q number that has never had a table cell of its own; decide whether to add one or drop "three suites" from the claim. The qualitative "gain grows with circuit size" holds if 25q (noise-dominated, near zero) is read as the floor rather than literally the smallest positive point; as a hard numeric range, "7.2–10.9%" should become something like "−1.4% to +15.4%" (or quote 36q/64q only, excluding the noise-dominated 25q point, if that's the intended reading).

This actually happened during the 2026-08-06 rerun campaign and had to be recovered by merging the pre-rerun 25q/36q blocks back in from `git show HEAD:code/results/results_pytket_layout.json`. **Always pass all three suites you want kept (`python3 bench_pytket_layout.py 25 36 64`), or merge manually afterward** — never invoke with a single suite unless you're prepared to lose the others.

### Appendix J — Entanglement-lifetime sensitivity (Table `tab:dmax`) — ❓ script missing, ⚠️ dSABRE column also stale
